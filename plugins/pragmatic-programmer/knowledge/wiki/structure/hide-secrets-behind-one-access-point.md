This is the worked form of [[information-hiding]]. McConnell's example is a unique object identifier: generating it with `id = ++g_maxId` in every constructor costs the least code per object, and still exposes two decisions that will change, how ids are made and what type they have (pp. 90-91). The same principle under another name is Plauger's: «Принцип Одного Верного Места» (p. 104), one right place to find a nontrivial piece of code and one right place to make a likely change.

## Rule

When a decision about representation or production is likely to change, make it in one place and have every use site go through that place: a routine (`NewId()`), a named type (`IdType`), a named constant (`MAX_EMPLOYEES`), or access routines in front of a data structure (pp. 90-92, 96). The book's reasoning on the identifier: reserving ranges, reusing freed ids, changing the order for security, adding a limit check, or making generation thread-safe each touch every scattered `++g_maxId`, and changing the type from integer to string touches every `int id` (pp. 90-91). Behind `NewId()`, however complex the change, «они не повлияют ни на какую другую часть программы» (p. 91).

The book also names the subtler leak of the type: showing that ids are integers invites callers to apply `>`, `<` and `=` to them (p. 91).

## Sign in code

- A primitive type stands for a domain value and is declared, stored and compared as that primitive across several modules (`int id` in signatures and fields, `id1 < id2` in callers).

This wiki assigns the neighbouring cases as follows. This page owns a representation decision visible at use sites whose code differs (a declaration here, a comparison there). The same production step or literal written at several sites (`id = ++maxId` in each constructor, the literal 100 as a bound) is [[dry]], whose repair, one place, is the same. A stored table or record layout known by several modules is [[single-owner-of-data-access]]. One quantity's primitive representation declared and compared across modules, so a change of representation spreads, is [[hide-secrets-behind-one-access-point]]; two different quantities sharing one primitive are [[replace-primitive-with-class]]; one kind of value spelled with a built-in type at many declarations, so that a change of representation means editing each one, is [[define-domain-types]]. Direct indexing of a shared structure is not this page's: access beside existing routines is [[access-routines-at-domain-level]], fields of a structure with no routines of its own written from several call sites are [[replace-direct-data-manipulation-with-adt]], and a structure made global so routines can reach it is [[global-data]]. Where user-interaction code belongs is a question of the project's architecture, out of this wiki's scope.

## When not to apply

- The decision is not likely to change and is not complex: the book scales effort to probability on [[anticipate-likely-changes]]. This wiki adds that a value local to one routine needs no access point; the sign requires several modules.
- The language or project already supplies the access point (an id generated by the store, a library type) and the code uses it.
- The book does not require a class for each secret; a typedef or a constant suffices (p. 96). This wiki reads that as a limit too, its own and not the book's: a one-line decision needs a named type or constant, not a full class with copy semantics, docs and tests.

## Repair

- Give the value a named type (an alias where the language has nothing more, a small type where it does) and use the name in every declaration; drop operations on it the domain does not need.
- Move production into one routine and call it from every site.
- Replace a size known at several sites with a named constant (p. 96).

## Before and after

```
class Order
    id: int
class Invoice
    id: int
    orderId: int

function latest(a: int, b: int): int
    if a < b then return b else return a
```

```
type Id                       -- callers see the name, not the representation
function newId(): Id          -- the only place that knows how ids are made

class Order
    id: Id
class Invoice
    id: Id
    orderId: Id
```

The comparison of ids is gone: ids are no longer known to be ordered.
