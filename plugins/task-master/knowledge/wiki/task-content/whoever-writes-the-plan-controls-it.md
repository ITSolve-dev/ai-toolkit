# Whoever Writes the Plan Controls It

This failure occurs when the record of a plan departs from what was actually decided, because whoever wrote it had the last word. Cohn's statement of it: "Worse, whoever has the keyboard can change what gets entered into the release plan." ([[cohn-agile-estimating-planning]] L3022). The passage is about an iteration planning meeting, despite the words "release plan".

## Two cases

In the first, a team agreed on twelve hours. The project manager at the keyboard entered eight, because "there’s no way it will take that long," although he was extremely unlikely to do the task (L3024-L3026).

In the second, everyone but the team lead agreed that a feature would be built as stored procedures, and he was asked to record "add stored procedures". He typed "Write data storage code." and Cohn draws the conclusion: "His message was clear: this issue has not been resolved." (L3028-L3032).

This wiki reads the second case as the more useful. A decision was reduced to a vaguer statement in the record, with no note that this had happened, and an executor reading that record sees an open choice.

## Observable signs

These signs are this wiki's. Each raises a question to check against the discussion.

- **In task text:** a generic title or scope where the discussion reached a specific decision.
- **In a task's history:** an estimate changed after agreement, with no reason, by someone who will not do the work.
- **Between conversation and task:** the discussion names a decision and the task omits it.

## Why it matters here

Cohn's remedy is cards that anyone can write on, which is facilitation and outside this wiki. The transfer here is ours: the plugin itself holds the keyboard. It writes tasks from conversations and documents, so any softening, tightening or reinterpretation it introduces has this same effect and nobody may notice. A task should state what was decided, and should mark what is still open as open, so that a vague phrase is never the only record of either ([[conversation-moves-into-the-task]], [[fact-stranded-outside-the-task]]).

## Trade-off

Recording exactly what was said can preserve a poor decision. The way to challenge one is to say so openly and leave the challenge visible, not to edit the record.

## Agent executor note

The mechanism gets sharper with an agent executing: a person reading "Write data storage code" might recall the argument, and an agent will decide the question by guessing ([[recoverable-versus-task-only-facts]]). Cohn's cases involve authority between people, and this wiki keeps only the difference between record and decision.
