# Overview

This wiki is the reference the `task-master` plugin judges from when it cuts, sizes, orders, moves, lays out or explains work for a few people steering an AI agent. A rule stored here carries the sign that reveals its violation, so the same page advises and audits.

## How it is organized

Pages are grouped by the question someone organizing work arrives with. A methodology's position is a section on the page where it differs, not a tree of its own.

| Group | Question |
|---|---|
| `cutting-work` | How do I cut this? |
| `task-content` | What must a task carry? |
| `sizing` | What does it cost, and when is it too big? |
| `ordering` | What comes first? |
| `intake` | What do I do with what came in? |
| `work-states` | What state is this in? |
| `moving-work` | What may move? |
| `periods` | What fits in a period, what is promised, and when will it be done? |
| `reading-history` | What actually happened? |
| `showing-work` | How do I show it? |

## Where to start

To cut a request, read [[story-splitting-patterns]], and to spot one that needs cutting, read [[compound-task-text-signs]]. To check a task before an agent takes it, read [[conversation-moves-into-the-task]] and [[recoverable-versus-task-only-facts]]. To size it, read [[story-points]] and [[estimation-scale]], and for what a size may not be used for, read [[size-versus-duration]]. To decide what comes first, read [[prioritization-factors]] and [[ordering-by-value-and-urgency]]. To handle what came in, read [[triage-procedure]]. To classify stopped work, read [[waiting-versus-blocked]]. To audit a board, read [[judging-board-columns]] and first [[smell-is-not-a-finding]], and to design one, read [[mapping-workflow-states]]. To see which rule holds for a project's setup, read [[board-rules-by-setup]].

To fill a period, read [[filling-a-period]], and to forecast how many tasks fit from history, read [[throughput-monte-carlo]]. To give a date, read [[deriving-duration-from-velocity]] and [[velocity-range-forecast]], to protect one, read [[choosing-a-buffer]], and to run it again as facts arrive, read [[reforecasting-a-release-from-velocity]]. To explain plan against fact, read [[release-progress-forces]] and [[chosen-delay-versus-slip]]. To pick a chart, read [[which-chart-for-which-plan-question]].

Under a flow setup, start from [[steps-to-predictability]]. To read a board's history, read [[flow-metrics]] and [[how-much-flow-data]], to see what is stuck now, read [[work-item-age]], and to read its charts, read [[reading-a-cfd]] and [[reading-a-cycle-time-scatterplot]], with [[which-chart-for-which-plan-question]] to choose between them and [[capturing-flow-data]] before trusting a tracker's. To decide what a limit should do, read [[wip-control]] and [[conservation-of-flow]]. To promise an item, read [[service-level-expectation]], and to give a date, read [[forecast-range-and-probability]] and [[throughput-monte-carlo]]. To decide whether estimates should still drive dates, read [[dropping-estimates-for-flow-forecasts]]. [[siemens-hs-case]] holds the setting behind the case numbers quoted across these pages.

[[unit-of-work]] fixes the vocabulary, because the sources use "story" and "task" differently from this wiki. [[synthesis]] states what the sources amount to together.
