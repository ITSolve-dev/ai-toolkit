A **completion criterion** is "the condition that tells the agent the work is done"
([[writing-for-agents-reference]], L65). The source grades it on two properties that vary
independently.

## Clarity

"Can the agent tell done from not-done?" A vague bound — the source's example is "understanding
reached" — invites **premature completion**: "ending the step before it is genuinely done,
attention slipping to *being done*" (L67).

The stated mechanism is a pull and a resistance. Work still visible ahead supplies the pull; the
sharpness of the current bound is the resistance. The repair order matters and is given explicitly:
"**sharpen the bound first** (local and cheap); only if it is irreducibly fuzzy *and* you observe
the rush", restructure so the later work is out of view (L67).

## Demand

"How much it requires. 'Every modified model accounted for' forces thorough work where 'produce a
change list' does not" (L68). Both criteria are equally clear; they differ in what they oblige.

The source separates demand from structure: it "is not step-bound: 'every rule applied' binds a
body of flat reference just as 'every step done' binds a sequence, which is how an all-reference
document still carries an exhaustiveness bar" (L68). This wiki takes that as the point of transfer
to documents that contain no steps at all: a set of requirements can carry a completeness
obligation without being a procedure.

"The strongest criteria are both checkable and exhaustive" (L70).

## Why the two properties must be graded separately

Collapsing them produces the two commonest defects in an acceptance criterion, and each looks like
the other's virtue:

| Clear | Demanding | What it reads as |
|---|---|---|
| yes | no | Precise and weak — satisfiable by the minimum ("a change list exists") |
| no | yes | Ambitious and unfalsifiable — "the system is robust" |
| yes | yes | The target |

## The symptom

**A criterion satisfied by producing an artifact rather than by reaching a state.** "Write the
migration plan" is met by a file existing; "every table with a foreign key accounted for in the
migration plan" is met only by the work. Read each criterion and ask what the cheapest thing is
that satisfies it as written — that answer is what the document actually asked for.

**A quantifier absent where one is meant.** *Every*, *each*, *all* are what carry demand; a
criterion phrased without one is usually asking for exhaustiveness it did not state.
