> **Sprawl** is the failure mode here: a document simply too long, even when every line is live and
> unique. Attention thins across the excess, and every extra line is one more to keep relevant. The
> cure is the ladder: disclose reference behind pointers, and split by branch or sequence so each
> path carries only what it needs.
>
> — [[writing-for-agents-reference]], L61

This wiki keeps the page because of the concessive clause. Every other cutting rule collected here
is a test on a *passage*: is this volatile ([[the-changeability-test]]), is this mechanism
([[state-the-commitment-not-the-means]]), is this duplicated, is this stale. Sprawl is what remains
when every passage passes its test and the document is still too long. No per-passage test can find
it, because there is no offending passage.

## Two costs, on different parties

The source names both in one sentence. "Attention thins across the excess" is a cost on the reader,
the same effect [[attention-budget]] measures. "Every extra line is one more to keep relevant" is a
cost on the author, paid at every future edit — and it is the one that compounds, because a
document nobody can keep current becomes wrong rather than merely long. See [[pruning-a-document]]
on the sediment this produces.

## The cure is relocation, not deletion

The stated remedy is "the ladder" ([[the-information-hierarchy]]) and splitting — not cutting. This
matters, because sprawl is the one defect here whose obvious repair would violate the floor.
Deleting live, unique material to shorten a document removes obligations, which is exactly what
[[minimal-is-not-short]] forbids: "minimal does not necessarily mean short". A sprawling document
is fixed by moving material to where only the readings that need it pay for it, and by splitting
paths so each carries its own share.

Where relocation genuinely has nowhere to go, the honest reading is that the *subject* is too
large rather than the document — the same diagnosis [[design-doc]] records for a design document
that runs far past its genre's range.

## The symptom

**Length that survives every other check.** The check is run in that order and only reaches this
page last: apply the passage tests, apply [[pruning-a-document]], and then look at what is left. A
document still long after all of them has a placement problem, and the branching test in
[[the-information-hierarchy]] locates it.

A second, cheaper symptom: **a reader who must read the whole document to act on any part of it.**
That is a path carrying material other paths needed — visible by taking one branch the document
handles and marking every block that branch does not use.
